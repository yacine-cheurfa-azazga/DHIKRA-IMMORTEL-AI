Abstract

DHIKRA QUAD SYSTEM AI is the public demonstration of the QUAD SYSTEM AI architecture (TR-2026-QUAD-0018, v2.6). It describes a verifiable ethical control layer placed between a human and an AI. The human enters the data and makes the decision, the AI proposes solutions, and the control layer filters, records, and can abstain. The AI may be a conventional AI; the control layer is independent of any particular AI.

The control layer relies on a validated rule-based inference core with three fundamental properties:

  • Determinism. With identical inputs, software version, configuration, and rule set, the core produces identical, reproducible outputs.
  • Explicit abstention. If the certainty score C(x) is below the threshold τ = 0.85, the system returns an explicit abstention message and provides no answer. This threshold is an uncalibrated design choice: it must be set from a risk-coverage analysis on a held-out labelled set. Abstention limits unjustified answers; it does not make the answers given correct.
  • Sealed memory. Validated entries are append-only and chained by a cryptographic hash (SHA-256). Any modification of an entry invalidates the following chain, which makes tampering detectable without guaranteeing confidentiality. Temporary session data is kept separately and deleted on request.

The core source code, full protocols, detailed formulas, exact inference rules, and internal documentation are confidential and unpublished. This page provides only the public specification and the proof of dating. This version claims no certification, regulatory approval, formal verification, or performance.

Principle of operation

Human (keyboard) → AI proposes → Respect-Check → Human validates → Sealed memory
StepActorRole
1HumanEnters the request and keeps the final decision. No action is taken without human intervention.
2AIProposes a text, a plan, or execution instructions (quadrant Q2).
3Respect-CheckFilters the proposal with a colour code: green, execution possible; orange, review required; red, blocked.
4Human validationThe human approves or refuses. For a physical action, validation goes through the ILM tablet (element 3).
5Sealed memoryThe validated entry is recorded append-only, hash-chained, and sealed by DHIKRA SOURCE via the CCSS protocol.

When the certainty score C(x) is below τ, the core abstains instead of answering.

Respect-Check. Green: execution possible. Orange: review required. Red: blocked. It filters action orders and memory entries.

Operating modes

The control layer is identical in all modes. What changes is where the AI runs, and therefore which claims apply.

ModeWhere the AI runsOffline claimDeterministic claim
A. Local AIOn the device, disconnectedApplies to the whole systemControl layer only
B. Institutional networked AIClosed institutional network (ILM tablet, restricted Wi-Fi)Applies to the control layer; the AI is reachable only on the institutional networkControl layer only
C. Conventional online AIAt an external providerDoes not apply to the AI; the control layer itself stays offlineControl layer only

Deterministic claims never apply to the AI's own outputs.

The four quadrants

The quadrants are cross-cutting design axes, applied to the core and to every module.

QuadrantAxisRole in the flow
Q1SOURCEValues, intent, sealed memory, and the RAHMA (رحمة) cultural alignment protocol. It is the heart of the control layer.
Q2LOGICThe language model, local or conventional, processes text, then plan, then execution instructions. Outputs are validated by the MICAE protocol before being sealed.
Q3VISIONPredictive modelling of the real world using V-JEPA 2-type latent embeddings. Anticipates states t+1 to t+3 before any action.
Q4ACTIONKinematic control of a robotic arm (Franka). Executed only after human validation and a positive Respect-Check on the ILM tablet, per the CCSS protocol.

The learned components (Q2, Q3, Q4) are outside the deterministic claims of this document. Determinism is specified only for the rule-based core.

Governance and validation

  • CCSS (Secure Control, Certification and Sealing). Sealing by cryptographic fingerprints; certification of action orders by Respect-Check and human validators; traceability of the orchestration core's decisions.
  • MICAE protocol. A memory entry is valid only when the human, animal, and environmental validators agree. DHIKRA SOURCE then seals it.
  • Consent-based governance. Decision by the local community. Municipal council approval is mandatory for any critical use. Right of objection guaranteed before closing a memory site.

Limitations

  • Determinism is specified only for the rule-based core, not for the AI's outputs.
  • With a conventional online AI, requests leave the device and are subject to the provider's terms.
  • No formal verification has been performed. Security properties require an explicit threat model and independent testing.
  • Regulatory compliance (civil drones, food and veterinary information) has not been assessed. No certification is claimed.
  • Abstention and filtering reduce unjustified answers but do not guarantee the correctness of the answers given.
