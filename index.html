Abstract

This repository is the public showcase of the QUAD SYSTEM AI architecture. It documents a rule-based inference core that runs offline, with an explicit abstention rule, a hash-chained memory with session purge, five domain elements and a governance layer. The document separates what is designed from what must still be measured, and it states what is not claimed. Selective classification, certainty-factor scoring and hash-chain time-stamping are established techniques. The contribution claimed is their specific combination and instantiation, which has not yet been evaluated. The software core is not published; this site publishes the specification and the evidence of dating only.

Governance and validation

  • CCSS, Contrôle, Certification et Scellage Sécurisé. Sealing by cryptographic fingerprints; certification of action orders by the Respect-Check ethical filter and by human validators; traceability of decisions made by the orchestrating core.
  • MICAE protocol. A memory entry is treated as valid only when human, animal and environmental validators agree; DHIKRA then seals it.
  • Consent governance. The local community decides. The local council gives its assent, which is mandatory for any critical use. Cultural alignment runs through SOURCE and the RAHMA protocol. Anyone may object before a memory is sealed.
  • Respect-Check. An ethical check showing green, orange or red, used to filter action orders and memory entries.

Requirements

  • REQ-1 Determinism. Identical input, software version, configuration and rule set give identical output. to measure
  • REQ-2 Traceability. Each output records the identifiers of the rules applied, in order. to specify
  • REQ-3 Abstention. If C(x) is below τ, the system returns the abstention message and no substantive answer.
  • REQ-4 Integrity of sealed memory. Validated entries are append-only and hash-chained, so modification is detectable. to measure
  • REQ-5 Session purge. Transient session data is deleted on request. to measure
  • REQ-6 Offline operation. No outbound connection during operation, except the institutional scope of N°3. to measure

Inference and abstention

Let x be an input and R = {r1, ..., rn} a finite, validated rule set. The output is the ordered application of the rules.

y = R(x)

C(x) = g(s1(x), ..., sm(x)), with C(x) in [0, 1]

abstain if C(x) < τ, with τ = 0.85

s1 measures the completeness of the input, s2 the exact match to the rules, and s3 the absence of ambiguity. The aggregation g is not yet fully specified. to specify The value τ = 0.85 is an uncalibrated design choice; it must be set from a risk-coverage analysis on a held-out labelled set. to measure

Abstention limits unsupported answers. It does not make the answers given correct, so error rates among answered inputs must be reported separately.

Sealed memory and purge

h_i = H(e_i || h_(i-1))

Validated entries form an append-only hash chain, so modifying any entry changes every later hash. This gives tamper evidence, not confidentiality. Session data is kept apart and deleted on request; a purge is verified by inspecting every storage location.

Limitations

  • Determinism is specified for the rule-based core only. Learned components are out of scope.
  • Abstention reduces unsupported answers. It does not prevent errors on answered inputs.
  • τ = 0.85 is an uncalibrated design choice.
  • No formal verification has been performed. Security properties require an explicit threat model and testing, and are not asserted here.
  • Domain performance depends on datasets that have not yet been described.
  • Regulatory compliance has not been evaluated. No certification or regulatory approval is claimed.
  • The software core is not published. This site gives the specification and the evidence of dating, not the code.

Related work: Chow (1970) analysed the reject option; El-Yaniv and Wiener (2010) formalised selective classification in terms of risk and coverage; Geifman and El-Yaniv (2017) extended it to deep networks. No systematic literature review has yet been carried out, so no priority claim beyond the specific combination is made.
